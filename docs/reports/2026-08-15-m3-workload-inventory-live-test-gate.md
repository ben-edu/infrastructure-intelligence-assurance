# Milestone 3 Workload Operational Inventory Live Test Gate — 2026-08-15

## Status

Pending management-host live acceptance.

## Scope

Validate the first workload-centric Dynamic Operational Inventory / CMDB projection against the real `k3s-main` evidence loop.

## Required acceptance evidence

1. Repository tests pass.
2. Existing Kubernetes and Git observers remain healthy.
3. No Kubernetes RBAC permission is added.
4. `inventory.json` and `inventory.md` are generated by the normal observer run.
5. Inventory workload count matches the current observed Deployment + StatefulSet + DaemonSet membership.
6. `mutation_allowed` is `false`.
7. Workload entities preserve observed evidence IDs and freshness.
8. Service relationships retain `SELECTOR_MATCH_INFERENCE` basis.
9. Ingress route candidates retain `COMPOSED_INFERENCE` basis.
10. PVC links retain observed-reference basis.
11. The existing `Ingress/validation/nginx-validation` host drift is surfaced as related attention on `Deployment/validation/nginx-validation` without changing the workload's direct `IN_SYNC` comparison.
12. The existing `Service/monitoring/loki-headless` multiple-controller ambiguity is surfaced on the related workload entities without choosing a single controller owner.
13. Workloads not represented in the configured Git source are `OUTSIDE_DECLARED_SCOPE`, not automatically drifted.
14. No raw Secret values, environment values, ConfigMap payloads, credentials, or sensitive connection strings appear in the inventory artifact.
15. The read-only `iia-inventory` CLI can return summary, attention-only list, and an exact workload entity without additional infrastructure reads.
