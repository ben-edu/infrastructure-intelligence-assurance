## Goal

Project existing incident-candidate evidence into a compact operator-facing contract that helps answer which current signals may belong together, without promoting a candidate to a confirmed incident or root-cause conclusion.

## Source

```text
/var/lib/infra-assurance/evidence/incident-candidates.json
```

The source is already generated by the existing five-minute collector from current alert attention, Kubernetes event correlation, inventory, and change context.

This slice performs no live infrastructure query and does not change systemd, installed runtime, services, timers, permissions, RBAC, kubeconfig, or datastores.

## Adapter contract

Implementation:

```text
src/infra_assurance/incident_operator_adapter.py
```

Scope:

```text
INCIDENT_CANDIDATES_EXISTING_EVIDENCE_ONLY
```

The adapter projects only:

- aggregate incident-candidate counts;
- aggregate attention for incomplete source coverage, active candidates, or unknown candidate state;
- compact candidate metadata: candidate ID, state, supported scope, alert/event/change/drift/check counts;
- deduplicated live-verification entries;
- explicit truncation metadata;
- trust semantics.

It discards raw alert labels/details, raw Kubernetes Event details, impact-context entity details, change field details, drift field details, rationales, logs, and other source-specific payloads.

## Trust semantics

The adapter preserves:

```text
candidate_is_confirmed_incident: False
candidate_is_root_cause: False
suppressed_means_resolved: False
live_verification_required_before_action: True
mutation_allowed: False
```

A source domain that is not `COMPLETE` produces explicit UNKNOWN attention. Candidate absence under incomplete sources is not negative evidence.
