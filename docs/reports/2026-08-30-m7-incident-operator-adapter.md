# Milestone 7 — Incident Operator Adapter

Date: 2026-08-30
Status: ACCEPTED / MERGE-READY
Mode: read-only projection over existing `incident-candidates.json`

## Goal

Project existing incident-candidate evidence into a compact operator-facing contract that helps answer which current signals may belong together, without promoting a candidate to a confirmed incident or root-cause conclusion.

## Source

```text
/var/lib/infra-assurance/evidence/incident-candidates.json
```

The source is already generated by the existing five-minute collector from current alert attention, Kubernetes event correlation, inventory, and change context.

This slice performs no live infrastructure query and does not change systemd, installed runtime, services, timers, permissions, RBAC, kubeconfig, or datastores.

## Adapter contract

Implementation:

```text
src/infra_assurance/incident_operator_adapter.py
```

Scope:

```text
INCIDENT_CANDIDATES_EXISTING_EVIDENCE_ONLY
```

The adapter projects only aggregate candidate counts, compact candidate metadata, aggregate attention, live-verification entries, truncation metadata, and trust semantics. Raw alert labels/details, raw Kubernetes Event details, impact-context entity details, field-level change/drift details, rationales, logs, and other source-specific payloads are discarded.

## Trust semantics

```text
candidate_is_confirmed_incident: False
candidate_is_root_cause: False
suppressed_means_resolved: False
live_verification_required_before_action: True
mutation_allowed: False
```

A source domain that is not `COMPLETE` produces explicit UNKNOWN attention. Candidate absence under incomplete sources is not negative evidence.

## Accepted interpretation

Current evidence contains four ACTIVE incident candidates grouped conservatively by supported scope. One candidate has a related Warning Event. No exact recent change or exact drift was associated with these candidates in the current source artifact.

These are candidate groupings only. They are not confirmed incidents, root-cause conclusions, or authorization for remediation. Because `incident_source_status` is `PARTIAL`, the set of four candidates is not a complete negative statement about all possible incidents or signals.

## Trust boundary

- bounded `sudo` use was only for protected artifact read access during validation;
- no live infrastructure query was performed by this adapter probe;
- no source or derived artifact was written;
- no raw alert/Event payload was projected;
- no systemd, runtime, service, timer, RBAC, kubeconfig, permission, datastore, or infrastructure change occurred;
- `mutation_allowed=false` remains explicit;
- candidate grouping is not incident confirmation or root-cause proof;
- live verification is required before operational action.
